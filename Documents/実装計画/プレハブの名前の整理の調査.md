# プレハブの名前の整理の調査

| 項目 | 内容 |
| --- | --- |
| 状態 | **調査だけ。名前はまだ変えていない** |
| 作成日 | 2026/11/25 |
| 作成者 | Claude Code（依頼：小野田 喬） |
| 対象 | `StarSweepers/Assets/` のプレハブ65個（ブランチ `feature/adjust-parameter-onoda` の時点） |

## 目的

昔はこのリポジトリにSpaceJunk以外のゲームも入っていたので、ゲームで使う物には `SpaceJunk` を付けて見分けていた。
今はStarSweepersだけになったので、**見分けるための頭の文字を外したい**。どれに付いていて、外すと何に響くかを調べた。

## 結論

- 見分けるための頭の文字が付いているプレハブは **`SpaceJunk` の21個**。迷うものとして `SweeperPlayer`・`TestSupply` も挙げておく。
- **Unityエディタで名前を変えれば、ゲームそのものは動く。** シーンやプレハブ、オンラインの一覧（`DefaultNetworkPrefabs`）は名前ではなく、番号（GUID）で物をつないでいるため。
- 壊れるのは、**プレハブの場所を文字で書いている道具とテスト**（下の②）。名前を変えるのと同じコミットで直す必要がある。
- 大槻さんのまだ取り込まれていないブランチが、`SpaceJunkSession`・`SpaceJunkRound`・`SpaceJunkGoalScoreEffect` の3つを変えている。**名前を変える前に大槻さんと時期を合わせたほうがよい。**

## 名前を変えたときの影響

### ① Unityエディタで変えれば、つながりは切れない

- シーン・プレハブ・スポナーの出す物の一覧・`DefaultNetworkPrefabs` は、番号（GUID）で物をつないでいる。**Unityのプロジェクト画面で名前を変えれば番号は変わらない。**
- オンラインで物を見分ける番号（GlobalObjectIdHash）も、番号（GUID）から作られる。名前を変えても変わらない**はず**。変えたあとに `SweeperOnlineTests` を流して確かめる。
- **OSのファイル操作（エクスプローラーや `git mv`）で変えてはいけない**（`.meta` との対応が崩れる）。

### ② 場所を文字で書いている道具・テスト（直さないと動かなくなる）

ゲームが動いている間に名前でプレハブを探す処理は**無かった**（`Resources` に置いているプレハブには `SpaceJunk` が付いていない）。
影響があるのはエディタの道具とテストだけ。

| ファイル | 書いているプレハブ |
| --- | --- |
| `Scripts/Game/Camera/Editor/SpaceJunkCameraSetup.cs` | StageCamera |
| `Scripts/Game/Gimmick/Editor/StageBarrierSetup.cs` | Round |
| `Scripts/Game/Match/Editor/ElectricDebrisSetup.cs` | Circuit・Plate |
| `Scripts/Game/Match/Editor/GoalEffectSetup.cs` | GoalScoreEffect・Round |
| `Scripts/Game/Match/Editor/GoalEffectTests.cs` | Plate |
| `Scripts/Game/Match/Editor/SpaceJunkGoalScoreEffectSetup.cs` | GoalScoreEffect・Round（作る物の名前も `"SpaceJunkGoalScoreEffect"`） |
| `Scripts/Game/Match/Editor/SpaceJunkRoundPrefabSetup.cs` | Round（作る物の名前も `"SpaceJunkRound"`） |
| `Scripts/Game/Player/Editor/PlayerNameTestSetup.cs` | Session |
| `Scripts/Game/Player/Editor/SweeperOnlineTests.cs` | NetworkManager・Plate |

`SweeperPlayer` も変える場合は、次の12ファイルも直す（`PlayerNameTestSetup` と `SweeperOnlineTests` は上の表と同じファイル）：
`PlayerSeatTestSetup`・`SceneBuildTools`・`PlayerNameTestSetup`・`SupplyTugTests`・`SweeperBendTests`・`SweeperCarryThrowTests`・`SweeperDistanceModeTests`・`SweeperHeavyBotTests`・`SweeperOnlineTests`・`SweeperReelGravityTests`・`SweeperWhipSetup`・`SweeperWhipTests`

説明の文（動きには関係ない）にも名前が出ている：
`SpaceJunkBombPoints.cs` と `SpaceJunkLobbyFixedSpawner.cs` の Tooltip、`TitleConnection.cs` と `TitleCreateRoom.cs` のエラーの文。

### ③ シーンに置いた物の名前は変わらない

ステージのシーン16個（`Scenes/Stage/` の14個と `WuStage/longstage_01`・`02`）には、`SpaceJunkRound`・`SpaceJunkSpawner` という名前の物が置かれている。
カメラの `SpaceJunkStageCamera` と、得点の演出の `SpaceJunkGoalScoreEffect` もシーンに2つずつある。
**プレハブの名前を変えても、シーンの中の物の名前はそのまま残る**（シーンが名前を持っているため）。

- 名前で物を探すコードは無いので、**残っていても動きは変わらない**。
- そろえるならシーン16個を直すことになる。ほかの人とぶつかりやすいので、**今は残すのがおすすめ**。

### ④ ほかのブランチとのぶつかり

develop にまだ入っていない大槻さんのブランチ（11/11〜12）が、次のプレハブを変えている。
名前を変えたファイルの中身をほかの人も変えていると、Gitが「消して新しく作った」とみなし、取り込むときにぶつかりやすい。

| ブランチ | 変えているプレハブ |
| --- | --- |
| `feature/Lobby3Dmodel` | SpaceJunkSession |
| `feature/debris-set-three` | SpaceJunkSession |
| `feature/goal-score-effect` | SpaceJunkGoalScoreEffect・SpaceJunkRound |
| `feature/stage-barrier` | SpaceJunkRound |

これらがもう別の形で develop に入っているかもしれない。**名前を変える前に大槻さんに確認する。**

### ⑤ ドキュメント

`Documents/` の40ファイルにプレハブの名前が出てくる。
今の説明（機能ドキュメント・スクリプトの説明・README のリポジトリ構成）は新しい名前に直す。
制作ログや変更ログのような**昔の記録は直さない**（その時点の名前として残す）。

## 今回の対象にしないもの（別に決める）

プレハブ以外にも `SpaceJunk` が付いている物がある。量が多く、ほかの人の作業とぶつかりやすいので、今回は外した。

| 種類 | 数 | メモ |
| --- | --- | --- |
| スクリプト（`SpaceJunkRound.cs` など） | 約120 | ファイル名を変えるならクラス名も変える必要があり、ほぼ全員のコードに響く |
| マテリアル（`Art/Materials/SpaceJunk*.mat`） | 9 | 番号でつないでいるので、変えても切れない |
| `Resources/SpaceJunkSkybox.mat` | 1 | **`SpaceJunkSkybox.cs` が名前で読み込んでいる**。変えるならコードも直す |
| シーン `SpaceJunkLobby.unity`・`SpaceJunkMapList.asset` | 2 | ビルド設定やマップの一覧にも関係するので別に調べる |

## 進め方の案

1. 上の ⚠ の名前と、`SweeperPlayer` を含めるかを決める。
2. 大槻さんに、④のブランチの取り込みと時期を確認する。
3. 名前を変える道具を一時的に作り、`AssetDatabase.RenameAsset` で21個まとめて変える（Unityの名前を変える機能と同じ。番号は変わらない）。
4. ②のファイルの場所の文字を直し、テストを全部流す（`SweeperOnlineTests` を必ず含める）。
5. ⑤のドキュメントを直し、1つのコミットにまとめてプッシュする。
