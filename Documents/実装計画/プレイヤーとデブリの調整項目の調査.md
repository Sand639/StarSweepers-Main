### 項目ごとの実装の方針

#### 段1：値の調整（1・3・2）

- **3 引っ張る時間**：`SweeperReel` の Critical Start を「Reel Seconds に対する割合」（いまの値なら 0.5）で持つように直す。そのうえで Reel Seconds を 2 → 2.2〜2.4 で試す。Critical Length（0.2 秒）と合図の Cue Lead（0.5 秒）は秒のままでよい。パターンBは Distance Reel Speed を 5.5 → 4.5〜5。
- **1 デバフの時間**：`SweeperPulledHit` をプレハブ `SweeperPlayer.prefab` に付けて、インスペクターで調整できるようにする（いまは起動時に付くのでコードの値）。電気（3秒）・爆弾（2秒）はそれぞれのプレハブ。
- **2 導火線**：引き寄せが長くなる分、`SpaceJunkBomb`・`KnockBackBoom` の Fuse Seconds（5秒）を見直す（投げてから爆発までの時間が短くなるため）。

#### 段2：小さな手触りの変更（8・12・7）

- **8 リキャスト**：`SweeperShooter` に「空振りの後」「投げた後」の待ち時間（例 0.3 秒／0.15 秒）を足す。待っている間はリングを少し暗く。
- **12 速さで変わるスタン**：`SweeperPulledHit` で、物資の速さを**位置の変化**から計算し、遅ければスタンなし、速いほどスタンと吹き飛ばしを強くする（下の 12 の案）。パターンAは動き始めが遅いので「初動はスタンなし」も兼ねる。
- **7 寄ってくる高さ**：重力を切ったので、つかんだときの高さのまま浮いて来る。**決まった高さ（例：床から 0.8m）にゆっくり寄せる**。高さがそろうと、12 の当たり方と前へはじく値（Forward Lift）が安定する。

#### 段3：近くで両手投げ（6）

いまのパターンAは、押すとどこでも「頭を越えて後ろへ」、押さなければ手前で「前へはじく」。これに**近いときの3つ目の動き**を足す。

1. 押した瞬間、プレイヤーと物資の距離が **Near Throw Distance**（例 2〜2.5m。両手を伸ばして届くくらい）以下なら「**持つ**」に入る。クリティカルの受付中なら、クリティカルを優先する（いまのクリティカルの位置は引き寄せの真ん中なので、ふつうは重ならない）。
2. 「持つ」：物資を、体の前・胸の高さの「両手の位置」へ短い時間（例 0.1 秒）で寄せ、体に付いて動くようにする。
3. **溜め（Windup。例 0.2 秒）**の後に、**向いている方向（体の正面）**へ投げる。着地点は「プレイヤーから何 m 前」（例：いまの後ろ投げの Back Distance 6m くらい）で、計算は今ある `BackThrowVelocity`（頂点の高さと着地点から初速を出す）を前向きに使う。**クリティカル（18m）より弱く、ふつうの引っ張り（6m）くらい**。
4. アニメーションが来たら、溜めの長さをアニメーションに合わせ、投げる瞬間をアニメーションのイベントで呼ぶ形にする（それまでは時間で投げる）。
- 「持つ」の間は、物資がほかの人に触れても**スタンさせない**（両手で持っている物は「引っ張っている最中」ではない扱い）。
- 投げは今の `Launch` を通るので、**オンラインもそのまま**ホストに投げを頼む形で動く。
- パターンB（距離で変わる）の「前へ投げる」区間も、同じ「持つ→投げる」に揃えると分かりやすい（揃えるかは試してから決める）。
- ボット（`SweeperBot`）は、近い所で押さないようにするか、近いときは前の味方ゴールへ向いてから押すかを決める（最初は「近い所では押さない」でよい）。
- **まだ決めていないこと**：押さずに手前まで来たときに、今どおり前へはじくか、自動で「持つ」に入るか。最初は**今どおり**にしておき、試して決める。

#### 段4：奪えないように（10）

- `NetSupply` に「この時刻までは誰もつかめない」値を足し、クリティカルで投げたときにホストが「飛んでいる時間＋少し」で設定する。
- ホストの `RequestClaimServerRpc` と、各PCの `SweeperReel.CanHook` の両方で見る。通信なしの検証シーン用に `HookableObject` にも同じ印。
- 段7 の引っ張り合いでも、**クリティカルの受付中と、クリティカルで飛んでいる間は引っ張り合いにならない**ようにこの印を使う。

#### 段5：エフェクトとその共有（13・14）

- **スタン★**：プレハブの子 `StunMarker` の中身を、頭のまわりを回る星にする（仮はコードで作り、デザイナーさんの素材が来たら差し替える）。
- **ノックバック**：当たった瞬間に、当たった位置へ「はじける輪＋星のかけら」を出す。出す場所は `SweeperPulledHit.Hit` と `MeteorStrikeEvent.ApplyPlayerImpact` の2か所。
- **全員に見せる**：
  - スタン … `SweeperNetSync` に「スタンが終わる時刻」（持ち主が書き、全員が読む値）を足す。他の人のPCでは、それを見て `PlayerStun` の**見た目だけ**動かす。
  - 当たった瞬間・電気 … クリティカルの光と同じ「ホスト経由で全員へ」の呼び出し（種類と位置）で配る。

#### 段6：見た目の差し替え（11・5）

**11 デブリのモデル**

- いまの物資のプレハブは、**全部 Unity の仮の箱（Cube）**で、1つの物に見た目・当たり判定・物理が全部付いている。
- 共有フォルダの素材（2026/11/24 時点）：

  | ファイル | 置き換え先の案 |
  | --- | --- |
  | `SM_Debris_Common_SteelPlate` | 装甲板（`SpaceJunkPlate`） |
  | `SM_Debris_Common_Components` | 回路基板（`SpaceJunkCircuit`） |
  | `SM_Debris_Common_DrumCont` | 燃料タンク（`SpaceJunkFuel`） |
  | `SM_Debris_Rare_Parabola` | アンテナ（`SpaceJunkAntenna`） |
  | `SM_Debris_Rare_Engine` | エンジン（`SpaceJunkEngine`） |
  | `SM_Bomb` | 爆弾（`SpaceJunkBomb`・`KnockBackBoom`） |
  | `SM_Debris_Common_AK`・`BrokenDisplay`・`EnergyBattery`・`Exhaust`・`MetalCap`・`Products`・`RobotArm`・`Transportbot` | **いまの種類（5種類）に当てはまる物が無い**。特殊デブリ（`SpaceJunkSpecial`）や、同じ種類の見た目違いに使えそう |

  **割り当ては名前から推測した案。デザイナーさんかプランナーさんに確認してから置き換える。** 素材の種類（5種類）は点数とデブリセットのお題に使われているので、勝手に増やさない。
- やり方：
  1. fbx を `Assets/Art/Models/` に入れる（今あるモデルも、ここにフォルダ分けせず置いてある。**新しくフォルダを作るなら先に確認**）。テクスチャは共有フォルダにまだ無いので、マテリアルは仮。
  2. 物資のプレハブは、一番上（Rigidbody・BoxCollider・点数などの部品）を残し、**仮の箱の見た目（MeshFilter・MeshRenderer）を外して、モデルを子として置く**。
  3. BoxCollider の大きさと中心を、モデルに合わせ直す。
  4. **見た目の部品を指している欄を付け直す**：`SpaceJunkMaterial` の色を塗る先（Tint Renderers）と、爆弾の点滅（Blink Renderers）は**インスペクターで Renderer を直接指している**ので、仮の箱を外したら新しいモデルの Renderer を入れ直す。光る縁取り（`SweeperItemGlow`）は子のモデルまで探すので、そのままでよい。クリティカルの金色の縁取り・白く光る（`SweeperReel`）も、差し替えた後に光るか確かめる。
  5. 色を塗る（種類ごとの色）を本物のモデルにも続けるかは、デザイナーさんに確認（モデルの色を活かすなら塗らない）。
  6. `使用素材とライセンス.md` に記録する（チームのデザイナーさんの制作物）。
- **プレハブの編集になる**（`Prefabs/Item/` の各プレハブ）。他の人が触っていない時にやり、変えたプレハブを報告する。

**5 リング**

- `SweeperRing` に「形ごとの見た目の値」（大きさ・太さ・浮かせる高さ・星のへこみ）の表を足し、形が変わったときに切り替える。表に無い形は今の共通の値を使う。
- 値はプレハブ `SweeperPlayer.prefab` に保存する（編集を報告）。

#### 段7：引っ張り合い（9）

目標：**2人が同じ物資を光線でつかんだら、物資を2本の光線が引き合い、振り回すなどして力で勝った側が残り、負けた側の光線が切れる。**

**考え方**：今ある「光線がちぎれる」仕組み（`SweeperReel` の Snap Strain：引きたかったのに動けなかった距離がたまったら切れる）を、そのまま「負けた側が切れる」に使う。

1. **2人目がつかめるようにする**：いまは他の人がつかんでいる物資は光線がすり抜ける（`CanHook`）。引っ張り合いを許す物資なら、2人目もつかめるようにする（ホストが2人目を受け付ける）。
2. **物資はホストの物理で動かす**：2人目が来たら、ホストが物資の持ち主を自分に戻し、「引っ張り合い中」にする（2人の番号を覚える）。
3. **力の計算（ホスト）**：それぞれの光線を「プレイヤーの手から物資へ張ったばね」と考え、物資に2つの力を加える。
   - ばねの強さは、プレイヤーと物資の距離が縮まらないほど強くなる（引いている感じ）。
   - **体を回す速さ・歩いて離れる速さを力に足す**（無理やり振り回すほど強く引ける）。プレイヤーの位置と向きはホストに届いているので、追加の通信は少ない。
4. **どちらが切れるか**：それぞれの光線ごとに「引きたいのに物資が来なかった（離れていった）距離」をためる。**先に Snap Strain を超えた側が切れる**＝相手のほうが力が強かったということ。残った側は、いつもの引き寄せに戻る（持ち主もその人へ）。
5. **長引いたら**：一定時間（例 3 秒）で決着しなければ、両方切れる。
6. **各プレイヤーのPC**：引っ張り合いの間は物資を自分で動かさず、ホストから届く位置へ光線を描くだけ。自分が切れたかはホストの値を見て知り、切れたら光線がちぎれる演出。
7. **ボット**：引っ張り合いになったら、物資から離れる方向へ歩きつつ押し続ける（最初はこれだけ）。
- 新しい部品（例：物資側の `SupplyTug`）に中身を書き、`SweeperReel` はそこへ「引っ張り合いに入った・抜けた」を知らせるだけにする（1600 行ある `SweeperReel` をこれ以上大きくしないため）。
- まず**通信なしの検証シーン**（`Scenes/Test/SweeperTugTest`。体を2つ置き、片方はボット）で手触りを作り、決まってから通信に載せる。
- 重い物（引きずるだけの特殊デブリ）と爆弾で引っ張り合いを起こすか、味方同士でも起こすかは、作りながら決める（最初は「起こす」で作り、スイッチで切れるようにする）。

## 2. 爆弾の即爆

**いま**：

- 爆弾は**光線でつかんだ瞬間に火がつき、5秒で爆発**（`ExplosiveObject.fuseSeconds`）。
- 「**引っ張っている最中**の爆弾が人に当たった」ときだけ、その場ですぐ爆発（`SweeperPulledHit` → `ExplosiveObject.ExplodeNow` / オンラインは `NetBomb.RequestDetonate`）。
- **投げたあと飛んでいる爆弾は、人や床に当たっても爆発しない**（残り時間が来るまで転がる）。

**案（「即爆」が「投げた爆弾がぶつかったら爆発」の意味なら）**：

- `ExplosiveObject` に「投げたあと、最初に何かへ当たったら爆発する」スイッチ（例：`Explode On Impact After Throw`）を足す。
- 投げた直後に自分の足元で爆発しないよう、**投げてから 0.1〜0.2 秒は当たっても爆発しない**時間を入れる。
- 判定は**ホストだけ**で行う（投げたあとはホストが物資を動かしている。`NetSupply.RequestThrowServerRpc` で持ち主がホストに戻る）。爆発させるのは既にある `NetBomb` の「全員で爆発」の流れを使う。
- 「床に当たっても爆発／人に当たったときだけ爆発」のどちらにするかは選べるようにしておく。

**確認したいこと**：「即爆」は ①投げた爆弾がぶつかったら爆発 ②導火線をもっと短く ③つかんだらすぐ爆発 のどれか。

## 3. デブリを引っ張る時間を少し遅くする

**いま**：パターンA（いつもの引き寄せ）は**時間で決まる**。Reel Seconds（いまは 2 秒）で、どの距離からでも手前に着く。
パターンB（距離で変わる）は**速さで決まる**（Distance Reel Speed 5.5m/秒）。

**案**：

- プレハブの `SweeperReel` の **Reel Seconds を 2 → 2.2〜2.4** にする（パターンBなら Distance Reel Speed を 5.5 → 4.5〜5）。
- **注意：Critical Start は秒で決まっている。** Reel Seconds だけ伸ばすと、クリティカルの位置が相対的に手前（早い側）へずれる。
  いまと同じ割合（真ん中）に保つなら、**Critical Start も同じ割合で伸ばす**（2.4 秒なら 1.2 秒）。
- 何度も調整するなら、Critical Start を「Reel Seconds に対する割合」で持つように直すと、片方を変えるだけで済む（小さなコード変更）。
- ボットは `reel.ReelSeconds`・`CriticalWindowEnd` を読んでいるので、**値を変えればボットも付いてくる**。

## 5. リングの形ごとの変数を保持

**いま**：足元のリングの形は、**チームの中で何人目か**で 円→三角→四角→星→六角形 と決まる（`SweeperNetSync.ShapeIndex`）。

**案（「形ごとに見た目の値を持たせたい」の意味なら）**：

## 6. 近くにいたら投げる、遠くからはプレイヤー基準

**いま**：パターンAで引き寄せの途中で押すと、**どこで押しても「プレイヤーの中心から 6m（クリティカルは 18m）後ろ」に落ちる**ように初速を計算している（`SweeperReel.ThrowBack` → `BackLanding`）。
遠くで押すと、物資は自分の頭を越えて長い距離を飛ぶ。近くで押しても着地点はほぼ同じ。

**案（「近くなら物資から投げる、遠くならプレイヤーから何 m 後ろ」の意味なら）**：

- 押した瞬間の**プレイヤーと物資の距離**で分ける（例：`Near Throw Distance` 3m）。
  - 近い：物資の位置から、決まった速さと高さで投げる（**物資基準**。飛ぶ距離はいつも同じ）
  - 遠い：今まで通り「プレイヤーの何 m 後ろ」に落ちる（**プレイヤー基準**）
- 今ある「Throw Follow Switch（前半／後半の切り替え）」は**引き寄せの進み具合**で切り替えているので、これを**距離**で切り替える形に直すのが一番小さい変更。
- ボットの投げ先の見積もり（`SweeperBot`）も、同じ計算を使うよう直す必要がある。

**確認したいこと**：①近い・遠いの境目は何 m か ②近いときの「投げる」は前・後ろどちらか ③クリティカルにも同じ分け方をするか。

## 7. 重力のあるなしの値の修正

**いま**：つかんでいる間は重力が無いので、**つかんだときの高さのまま**浮いて寄ってくる。重力ありの頃に合わせた値が合わなくなっている可能性がある。

| 合わなくなりそうな値 | 理由 |
| --- | --- |
| 寄ってくる高さ | 跳ねている途中でつかむと、高い所を浮いたまま来る。**頭の上を通ると「ぶつかってスタン」（#12）が起きない／起きすぎる** |
| Forward Lift（前へはじく上向きの速さ 1.5） | 重力ありの頃は床すれすれから飛んでいた。いまは浮いた高さから飛ぶ |
| Back Arc Height・Critical Arc Height | 放物線の頂点は足元から測るので、浮いた高さが違うと飛び方が変わる |
| Snap Strain・Strain Recovery（ちぎれる） | 床との摩擦で遅れる分を見込んだ値。摩擦が無くなったので、もっと敏感にできる |
| Max Drag Speed 40 | 摩擦が無い分、速く出やすい |

**案**：

- 「寄ってくる高さ」を**決まった高さ（例：床から 0.8m）にゆっくり寄せる**ようにする。浮く高さがそろうので、残りの値も合わせやすくなる。
- そのうえで上の値をプレハブで合わせ直す。
- 参考：体（`SweeperMover`）の落ちる速さ（gravity −20）は、`WorldGravity.Scale` を見ていない。いまはこのリポジトリに重力を変える仕掛けが無いので困らないが、**重力イベントを足すときは直す必要がある**。

**確認したいこと**：「値の修正」が上のどれのことか（特に気になっている動きがあれば教えてほしい）。

## 8. リキャスト（ほんの少し）の追加

**いま**：光線が戻った瞬間・投げた瞬間に、すぐ次を撃てる。待ち時間の仕組みは無い（`SweeperShooter`）。

**案**：

- `SweeperShooter` に `Recast Seconds`（例：0.2〜0.3 秒）を足す。光線が戻って Idle になったとき・投げ終わったときに「次に撃てる時刻」を記録し、それまでは押しても始めない。
- 「空振り」と「投げた後」で長さを変えられると調整しやすい（例：空振り 0.3 秒／投げた後 0.15 秒）。
- 待っている間は足元のリングを少し暗くすると分かりやすい（`SweeperRing` の色の透明度）。
- **自分のPCだけの話なので、通信は要らない。** ボットは押しっぱなしにするだけなので、待てば撃てる（念のためボットのテストを回す）。
- スタン中は今までどおり撃てない（別の仕組み）。

## 9. 引っ張り合い（物理）

**いま**：オンラインでは、**先につかんだ人の物**。他の人の光線はその物資をすり抜ける（`SweeperReel.CanHook`、`NetSupply.RequestClaimServerRpc` で2人目を断る）。
つかんだ人のPCへ物資の持ち主が移り、その人のPCの物理で動かしている。

**難しいところ**：持ち主が1人のPCに移る作りなので、**2人の力をそのまま物理で混ぜることができない**。

**案（通信でも成り立つ形）**：

1. 2人目がつかんだら、ホストが**物資の持ち主を自分に戻し**、「引っ張り合い中」にする（2人の番号を覚える）。
2. 2人はそれぞれ「自分のほうへ引く力」をホストへ送る（連打・スティックを倒すと強くなる、など）。
3. ホストが2つの力を足して物資を動かす（ここが「物理」の部分）。
4. 終わり方：どちらかの手前まで来たらその人の物／一定時間（例：2秒）で決着が付かなければ**光線がちぎれて両方離す**／どちらかがスタンしたら相手の物。
5. ボットは、引っ張り合いになったら押しっぱなし（またはあきらめる）だけ決めておく。

- 一番大きな変更。`SweeperReel`・`NetSupply`・`SweeperNetSync`・`SweeperBot` にまたがる。**専用の検証シーンを `Scenes/Test/` に作って**進める。
- **確認したいこと（企画）**：勝ち負けの決まり方、連打かどうか、味方同士でも起きるか、重い物でも起きるか。

## 10. クリティカルプルのとき、奪えないように

**いま**：投げた瞬間（`NetSupply.RequestThrowServerRpc`）に「つかんでいる人」が消える（−1 に戻る）ので、
**クリティカルで飛んでいる物資を、他の人が空中でつかめる**。

**案**：

- `NetSupply` に「この時刻までは誰もつかめない」（例：`protectedUntil`、全員が読める値）を足し、クリティカルで投げたときにホストが設定する。
- 長さは「飛んでいる時間＋少し」か、「床に着くまで」。
- `SweeperReel.CanHook` と、ホストの `RequestClaimServerRpc` の両方で見る（片方だけだと、ずれたときにつかめてしまう）。
- 通信なしの検証シーン用に、同じ印を `HookableObject` にも持たせる。
- #9 の引っ張り合いを作るなら、**クリティカルの受付中・クリティカルで飛んでいる間は引っ張り合いにならない**ようにする。

## 11. デブリの切り替え（当たり判定は Box）

**いま**：物資のプレハブ（`Prefabs/Item/` の Plate・Circuit・Fuel・Antenna・Engine・Special・Bomb・KnockBackBoom）は、**全部 BoxCollider 1つ**になっている。

**案（「デザイナーさんのモデルに差し替える」の意味なら）**：

- 一番上（Rigidbody・BoxCollider・HookableObject）はそのままにして、**見た目の子だけ差し替える**。当たり判定と点数の部品は触らずに済む。
- Box の大きさは、モデルの大きさに合わせて直す。手で合わせるのが大変なら「子のモデルに Box を合わせる」エディタのメニューを作れる。
- **プレハブの編集になる**ので、どのプレハブを変えたか報告する。

**案（「同じ種類の物資に、見た目を何種類か持たせて出るたびに変える」の意味なら）**：

- `SpaceJunkMaterial` に見た目の候補を持たせ、出すときに1つ選ぶ。オンラインでは**選んだ番号をホストが配る**（各PCでばらばらに選ぶと見た目が人によって違う）。
- Box は候補ごとに大きさを持たせるか、全部同じ大きさに収まるモデルにしてもらう。

**確認したいこと**：上のどちらか。

## 12. デブリは初動だけスタンなし or 速度によってノックバックとスタン時間増加

**いま**：引っ張っている物資に触れたら、**速さに関係なくいつも 1.5 秒スタン・9m/秒の吹き飛ばし**（`SweeperPulledHit.Hit`）。
つかんだ直後のほとんど動いていない物資に、そばに立っていた人が触れただけでもスタンする。

**案（両方まとめてできる）**：

- 物資の**速さ**を見て強さを変える。速さはぶつかられた人のPCで、**物資の位置の変化から計算する**（オンラインの他人の物資は、こちらでは物理が止まっていて `linearVelocity` が 0 のことがあるため）。
- 値の例：
  - `Min Stun Speed`（例 2m/秒）より遅い → **スタンなし**（軽く押すだけ、または何もしない）
  - `Max Stun Speed`（例 10m/秒）以上 → いちばん強い（スタン 2秒・吹き飛ばし 12m/秒）
  - その間 → 速さに合わせて強くなる
- パターンAの引き寄せは、動き始めが遅いので、速さで決めれば**自然に「初動はスタンなし」**にもなる。
- それでも足りなければ「つかんでから○秒は当たらない」も足せる（引っ張っている人の `SweeperReel.Elapsed` を見る）。
- 電気のデブリは、今まで通り専用の値（長く痺れる）を優先する。
- 変更は `SweeperPulledHit` の中だけで済む。吹き飛ばす向きのテスト（`SweeperPulledHitTests`）に、速さの計算のテストを足す。

## 13. スタンエフェクト（★）、ノックバックエフェクト（当たった瞬間）

**いま**：

- スタン中は、体が赤く点滅し、頭の上の印（プレハブの子 `StunMarker`）が回る（`PlayerStun`）。
- 当たった瞬間の演出は無い（電気のデブリだけ、体に電気が走る `ElectricSparks`）。
- クリティカルが決まったときの「星のかけらが飛び散る」（`SweeperShards`）がある。

**案**：

- **スタン（★）**：`StunMarker` の中身を、頭のまわりを回る星にする。形はデザイナーさんの素材が来たら差し替える。先にコードで仮の星（`SweeperShards` や `SweeperRing` の星の形を使う）を作っておける。
- **ノックバック（当たった瞬間）**：当たった位置に、はじける輪や星のかけらを一瞬出す。出す場所は `SweeperPulledHit.Hit`（引っ張った物）・`MeteorStrikeEvent.ApplyPlayerImpact`（隕石・爆風）の2か所に集めると、全部の吹き飛ばしで出る。
- 素材は `Prefabs/Effect/` に置く（フォルダは既にある）。
- **#14 と一緒に作る**（作ってから通信に載せ直すと二度手間になる）。

## 14. エフェクトが全員で共通に見えるように

**いま（大事）**：

- スタンは**ぶつかられた人のPCだけ**で起きている（`SweeperPulledHit` は自分の体だけを判定し、`PlayerStun.Stun` を自分のPCで呼ぶだけ）。
  **スタンを通信で配っていない**ので、**他の人の画面では、赤い点滅も頭の印も出ない**（吹き飛ぶ動きは位置が届くので見える）。
- 電気が走る演出（`ElectricDebris.PlayShock`）も同じで、ぶつかられた人の画面にしか出ない。
- クリティカルの光だけは、`SweeperNetSync` の `EffectServerRpc → EffectClientRpc` で全員に配っている。**これが手本になる。**

**案**：

- **スタン**：`SweeperNetSync` に「スタンが終わる時刻」を、体の持ち主が書いて全員が読める値（NetworkVariable）として足す。
  変わったら、他の人のPCでは `PlayerStun.Stun(残り秒数)` を**見た目のためだけに**呼ぶ（他人の体は動かしていないので、動けなくなる処理は関係ない）。ボットはホストが持ち主なので同じ形で動く。
- **当たった瞬間の演出・電気**：一回きりの出来事なので、クリティカルの光と同じ **ServerRpc → ClientRpc** で「種類・位置」を配る。
- 爆弾の爆発の演出は、もう全員の画面で出ている（`NetBomb`）。
