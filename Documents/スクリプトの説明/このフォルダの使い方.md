# スクリプトの説明（このフォルダの使い方）

コードの中のコメントを短くし、**詳しい説明はここに書く**ための場所（2026/11/6・大槻さんの方針）。

## 何をどこに書くか

| 書く場所 | 書くこと |
| --- | --- |
| コードの中（`///` のコメント） | **その関数が何をするかを1行で。** いつ・誰の依頼で・どういう経緯で、は書かない |
| このフォルダ | スクリプト全体の役割、画面や処理の流れ、プレハブとのつながり、気をつけること |
| `機能ドキュメント/` | 遊ぶ人から見て、その機能で何ができるか（今までどおり） |
| Git の履歴・ドキュメントの変更ログ | いつ・誰が・なぜ変えたか（経緯） |

## ファイルの置き方

`Assets/Scripts/` と同じフォルダ分けにして、**ファイル名はスクリプトと同じ名前**にする（コードから探しやすくするため）。

例：`Assets/Scripts/TitleScene/UI/TitleScreen.cs` → `スクリプトの説明/TitleScene/UI/TitleScreen.md`

すべてのスクリプトに作る必要は無い。整理したスクリプトや、読むのに説明が要る長いスクリプトから作る。

長いスクリプトは、**1つのクラスのまま、ファイルだけを機能ごとに分けてよい**（`クラス名.機能.cs`。C# の partial という書き方）。そのときは、ここに次の2つを書く。

- **ファイルの分け方**（どのファイルに何があるかの表）。**行数は書かない**（コードを直すたびにずれるため）
- **変数の置き場所**（入口のファイルに無い変数・定数が、どのファイルにあるか）。1つのファイルを開いただけでは、変数がどこにあるか分からないため

分けたスクリプトの入口のファイル（`クラス名.cs`）には、クラスの説明のコメントの最後に、ここの説明の場所を1行書いておく（コードから開いたAIが、説明に気づけるように）。

コードの働きを変えたら、ここの説明も同じときに直す（`Documents/README.md` の「ファイルを分けたスクリプトを直すとき」）。

## 1ファイルの中身（目安）

1. 一番上の表：スクリプトの場所・付いている場所・関係するドキュメント
2. 何をするスクリプトか（2〜3行）
3. 流れ（何がどの順で起きるか）と、主な関数
4. 気をつけること（触るときに壊しやすい所）
5. 変更ログ
