# 移行の道具の使い方

> ⚠️ **2026/11/5 に `Assets/` のフォルダを整理したので、この手順（旧リポジトリから道具で取り込み直す）は、もうそのままでは使えない。**
> 旧リポジトリと場所が違うため、取り込むとゲーム名のフォルダが作り直されて二重になる。必要な物は、`実装計画/フォルダ整理の対応表.md` を見て手で持ってくること。
> フォルダを対応表どおりに移動する道具（`フォルダを対応表どおりに移動する.cs.txt`）は、この整理で使った物。

旧リポジトリ（`Sand639/StarSweepers`。保管用）から、このリポジトリへ**本制作に必要なファイルだけ**を持ってくるための道具。
2026/11/4 の移行と、11/5 の取り込み直しで使った。**旧リポジトリの `develop` にまた変更が入ってしまったとき**に、同じ手順で取り込み直せる。

決め方の説明は `AIの申し送り.md` の「本制作だけのリポジトリへの移行」にある。

## 入っている物

| ファイル | 役割 |
| --- | --- |
| `一覧を書き出すエディタスクリプト.cs.txt` | Unity の中で動かす。宇宙ごみの3フォルダを起点に、参照しているファイルの一覧を書き出す |
| `本制作のファイルを集める.py` | 一覧にスクリプト同士の呼び出しを足して、このリポジトリへコピーする。ビルド対象のシーン一覧も絞る |
| `参照の漏れを調べる.py` | 持ってきたシーン・プレハブが参照している ID のうち、旧にあって新に無い物を探す（`--fix` で足す） |

## 手順

パスはこの PC（大槻さん）の例。`<作業用>` は一時ファイルを置くフォルダ。

1. 旧リポジトリを `develop` の最新にして、**Unity で開いていないこと**を確かめる。
2. `一覧を書き出すエディタスクリプト.cs.txt` を、旧リポジトリの
   `StarSweepers/Assets/Scripts/SpaceJunk/Editor/MainGameDependencyExporter.cs` としてコピーする（**一時的に置くだけ。コミットしない**）。
3. 画面なしの Unity で一覧を出す。

   ```
   "D:\011_Unity\Editor\6000.3.14f1\Editor\Unity.exe" -batchmode -nographics -quit -projectPath "D:\010_GitHub\StarSweepers\StarSweepers" -executeMethod MainGameDependencyExporter.Export -depsOut "<作業用>\main-game-deps.txt" -logFile "<作業用>\unity-export.log"
   ```

4. 2 で置いた `.cs` と、Unity が作った `.cs.meta` を消す（`git status` が空になること）。
5. コピーする（先に `--dry-run` を付けると、集計だけ出る）。

   ```
   "D:\999_Tools\Anaconda3\python.exe" -I "本制作のファイルを集める.py" --src "D:/010_GitHub/StarSweepers" --deps "<作業用>/main-game-deps.txt" --dest "D:/010_GitHub/StarSweepers-Main"
   ```

6. 漏れを足す。「コピーし忘れ: 0 件」になるまで繰り返す（フォルダの場所は `.py` の先頭の `OLD` `NEW` に書いてある）。

   ```
   "D:\999_Tools\Anaconda3\python.exe" -I "参照の漏れを調べる.py" --fix
   ```

7. 旧リポジトリで `Documents/` が変わっていたら、手で取り込む（このリポジトリ側で書き足した所を消さないこと）。

   ```
   git -C "D:\010_GitHub\StarSweepers" diff --name-status <前回取り込んだコミット> develop -- Documents
   ```

8. このリポジトリを画面なしの Unity で開き、ログに `error CS` が無いことを確かめる。
9. `AIの申し送り.md` の「本制作だけのリポジトリへの移行」に、どのコミットまで取り込んだかを書く。

## 気をつけること

- **5 は上書きと追加だけで、削除はしない。** 旧リポジトリで消えた・名前が変わったファイルは、このリポジトリに残る。
  `git diff --name-status <前回> develop` に `D` や `R` の行があったら、Unity エディタの中で消すこと。
- **このリポジトリで直したファイルも、5 で旧の内容に上書きされる。** 取り込み直す前に必ずコミットし、終わったら `git diff` で巻き戻った所が無いか見ること。
  こちらでの作業が進んだあとは、この道具ではなく、必要なファイルだけを手で持ってくるほうが安全。
- `5` は `<dest>` の1つ上のフォルダに `copied-files.txt`（コピーした物の一覧）を書く。要らなければ消してよい。
