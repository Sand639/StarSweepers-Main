## まとめ（整理するときに見る所）

### 1. 使われていないのは 9 本だけ

`CameraObstacleAvoid`・`SeeThrough`・`MovableBlock`・`MovingPlate`・`InputSeatTestHud`・`ScorePocket`・`PlayerController`・`PlayerNameTestHud`・`PlayerViewSwitcher`。
どれも、エディタの道具か、ほかの使われていない物からしか呼ばれていない。消す前の注意（ソウさんの制作物がある、道具も直す必要がある、など）は `使われていないファイルの調査.md`。

### 2. プレイヤーの体が「古い体」と「新しい体」の 2 つある（いちばん大きい整理の候補）

| | 古い体 | 新しい体 |
| --- | --- | --- |
| プレハブ | `Prefabs/Player/SpaceJunkPlayer.prefab` | `Prefabs/Player/SpaceJunkSweeperPlayer.prefab` |
| 体だけに付いている物 | `HookController`・`ThrowController`・`HookLine`・`HookProjectile`・`PlayerAimController`（合わせて約 4,300 行） | `Sweeper〜` で始まる物（`SweeperShooter`・`SweeperReel` など） |
| ボットの頭 | `SpaceJunkBot`（1,243 行） | `SweeperBot`（1,146 行） |

- シーンの NetworkManager（通信の管理役）には古い体が入っているが、**`SweeperOnlineSwitch` が遊ぶ前に新しい体へ入れ替える**。
  古い体は「新しい体のプレハブが見つからないときの予備」で、ふだんは動かない。
- ボットも 2026/11/5 から新しい体で出ている（`SpaceJunkSession` が、体に `SweeperShooter` が付いていれば `SweeperBot`、無ければ `SpaceJunkBot` を付ける）。
- 古い体の部品（`HookController`・`ThrowController` など）は、**ほかの 20 本以上のスクリプトからも呼ばれている**（`FishingNetSupply`・`HookableObject`・`SpaceJunkPlayerSetup` など）。
  古い体をやめる場合は、その呼び出しも一緒に片付けることになるので、**一度にやらず、段階を分けて**進めるのが安全。
- **古い体を残すか（予備として持っておくか）やめるかは、方針の判断**が要る。

### 3. 釣りの名前のまま、宇宙ごみで使われている物

`FishingNetPlayer`・`FishingPlayerController`（新しい体にも付いている）・`FishingNetSupply`・`FishingNetBomb`・`FishingObjectSpawner`・
`FishingMatch`・`FishingMatchUI`・`FishingStatusUI`・`FishingTeams`・`FishingNetPocket`。
**名前は釣りだが、宇宙ごみの土台として動いている**ので消せない。名前を変えるかどうかは整理の候補。
変える場合は、ファイル名とクラス名を同時に変え、呼んでいる所もすべて直す必要がある。ほかの人のブランチとぶつかりやすいので、**全員の作業が落ち着いた時期にまとめて**やるのがよい。

## 状態の見方

| 状態 | 意味 |
| --- | --- |
| ◎ シーン・プレハブ | ビルドに入るシーン、`Resources/`、実際の体のプレハブのどれかに付いている |
| ◎ 自分で生まれる | 再生を始めたときに、コードが自分で作る（`RuntimeInitializeOnLoadMethod`）。シーンには置かれていない |
| ○ スクリプトから | どこにも付いていないが、使われているスクリプトのコードの中で名前が出てくる |
| ◇ 古い体だけ | 古い体のプレハブにだけ付いている（上の 2）。ふだんは動かない |
| △ 通信の一覧だけ | 通信の一覧（`DefaultNetworkPrefabs.asset`）に登録されたプレハブにだけ付いている。LAN の最初の検証用など |
| △ Hansさんのステージだけ | ビルドに入っていない HansStage01 にだけ置かれている |
| × 使われていない | 上のどれでもない。エディタの道具からしか呼ばれない物も、ここに入る |
| ― 分けた一部 | `クラス名.機能.cs` の形のファイル。同じクラスをファイルだけ分けた物（partial）なので、使われ方は入口のファイル（`クラス名.cs`）と同じ |
| 道具 | `Editor/` の中にある、エディタでだけ動く物（メニューの道具・自動テスト・インスペクターの拡張）。ゲームには入らない |

「どこで使われているか」の書き方：

- 「全ステージ」 … ビルドに入っている STAGE（`STAGE_01`〜`07`、`STAGE_06^^`、`STAGE_07(New)`）のすべて
- 「ST01」など … その STAGE だけ
- 「呼ばれる：」 … そのスクリプトの名前をコードの中で使っている、使われているスクリプト

## 調べ方と限界

道具は `調査の道具/スクリプトの使われ方の一覧を作る.py`（読むだけで、何も変えない）。整理したあとに、下の「一覧」をこれで作り直すこと。

```
"D:\999_Tools\Anaconda3\python.exe" -I "スクリプトの使われ方の一覧を作る.py" "D:/010_GitHub/StarSweepers-Main" > 一覧.md
```

たどり方は `使われていないファイルの調査.md` の道具と同じ。ビルドに入るシーン（11）・`Resources/`・ProjectSettings・実際の体のプレハブを起点に、
ファイルの中の参照 ID（GUID）と、コードの中のクラス名をたどった。

**限界**：

- 「○ スクリプトから」は**コードに名前が出てくる**という意味で、その行が実際に動くかまでは分からない。
  たとえば `SpaceJunkBot` は「○」だが、実際に動くのは古い体のときだけ（上の 2）。
- クラスの名前とたまたま同じ言葉を使っていると、「呼ばれる」と出ることがある。
- 名前の文字列で実行時に読み込む物は拾いきれないことがある。**消す前には、ファイル名と GUID を `git grep` で探し直すこと。**
