## この機能は何か

**ゴールの輸送機の手すりを4方向にし、となりに地面がある側の手すりだけを、着地したときに床の下へしまう。**

- 前は、輸送機の手すりは3方向で、手すりの無い1方向がステージの中央を向いていた
- いまは**4方向とも手すりがある**。プレイヤーを乗せて飛んでくる間は、4方向とも囲まれている
- 輸送機がステージに着地すると、**となりに床がある側の手すりが、台座の穴へすっと沈んで消える**
- となりに床が無い側（ステージの外側など）の手すりは、そのまま残る（落ちないための柵になる）

モデルの変更は、**Hans さんに相談して了承をもらったうえで**行った（2026/11/12・小野田さんから）。

## 遊ぶ人から見た動き

| 場面 | 結果 |
| --- | --- |
| 1ラウンド目の始まり（輸送機がプレイヤーを乗せて奥から飛んでくる） | 飛んでいる間は手すりが4方向とも立っている |
| 輸送機が元の位置に着地した | 少しして、**となりに床がある側の手すりが 0.6 秒ほどで床の下へ沈み、消える**。そのあと 3・2・1 → START! |
| 2ラウンド目から（ステージを回る間に一緒に着地する演出） | 同じく、着地したときに沈む |
| ガラスマップ1・2・4（輸送機がステージの外側に付いている） | 中央側の1枚だけ沈む（前の見た目と同じ3方向になる） |
| ガラスマップ3・電車マップ2 など（輸送機がマスの中にある） | 床と接している側が全部沈む（2〜3枚） |
| ロビー・演出の無いシーン | 始まって 0.5 秒ほどで、となりに床がある側が沈む |
| ロビーのチーム床（赤・青）と練習用ゴール | どれも3方向が床と接しているので、入口側（南・東）を含む3枚が沈み、奥の1枚だけ残る（床の並びから計算した見込み。2026/11/12 の develop のロビー） |
| 残った手すりにぶつかる | 前と同じく、通り抜けられない |

## 試し方

1. Unity のメニュー **`Tools > StarSweepers > ゴールの手すりの検証シーンを作る`** を押す（`Assets/Scenes/Test/GoalFenceTest.unity` ができる）
2. 再生すると、0.5 秒ほどで手すりが沈む
   - 左の輸送機 … 前（奥）にだけ床 → **前の1枚**が沈む
   - 真ん中の輸送機 … 前・左・右に床 → **3枚**沈む
   - 右の輸送機 … 床なし → **4枚とも残る**
3. もう一度見たいときは、再生中にヒエラルキーで輸送機を選び、インスペクターの `SpaceJunkGoalFence` を右クリック →「手すりを上げ直す」
4. 試合では、`MainLoop/TitleScene.unity` から始めて、ガラスマップか電車マップ2を選ぶ

## モデルの変え方（`SM_Transporter.fbx`）

**元の作りはできるだけそのまま**にして、次の2つだけ変えた（Blender で編集）。

| 変えたこと | 中身 |
| --- | --- |
| 手すりを4方向にした | 手すりの無かった側（Unity で見て前＝+Z）に、反対側（後ろ）の手すり・中段の横棒・丸い台座2つを写して、180度回して置いた |
| 手すりを1枚ずつ別の部品にした | 手すり（パイプ＋中段の横棒）を、本体の子 `Fence_Front`・`Fence_Back`・`Fence_Left`・`Fence_Right` に分けた。**丸い台座は本体に残した**（手すりが台座の穴へ沈んで見えるように） |

- 本体の名前（`Transporter`）・材質（`M_Transporter2`）・UV・向き・大きさ・単位は元のまま
- **シーンからの参照は外れない**：本体の GameObject・Transform・MeshRenderer・MeshFilter・Mesh の番号（fileID）が元と同じなのを、別の Unity（6000.3.14f1）で取り込んで確かめた
- 共有フォルダの元のファイル（`共有フォルダ/20_デザイン素材/40_3D素材/01_Stage_01/SM_Transporter.fbx`）は**変えていない**（Hans さんの元データとして残す）

## 設定できる値（インスペクターの項目）

`SpaceJunkGoalFence` は再生時に自動で付くので、ふだんは何もしなくてよい。
**値を変えたい輸送機だけ**、シーンの輸送機に `SpaceJunkGoalFence` を手で付けて値を入れる（付いていれば、自動では付け足さない）。

| 項目名 | 意味 | 実装したときの初期値（目安。調整で変わる） |
| --- | --- | --- |
| Front / Back / Left / Right | その手すりをどうするか。**Auto**＝となりに床があればしまう／**Lower**＝いつもしまう／**Keep**＝しまわない | Auto |
| Lower Seconds | しまうのにかける秒数 | 0.6 |
| Lower Delay | 着地してから、しまい始めるまでの秒数 | 0.15 |
| No Round Delay | 試合の進行役が無いシーン（ロビー・検証シーン）で、始まってからしまい始めるまでの秒数 | 0.5 |
| Probe Distance | 手すりから外側へ何 m の所に床があるかを調べるか | 0.5 |
| Height Tolerance | 輸送機の床の高さから上下何 m までの面を「床」とみなすか | 0.5 |

**決まり（変えると壊れる）**：モデルの手すりの名前 `Fence_Front`・`Fence_Back`・`Fence_Left`・`Fence_Right` は変えないこと（名前で手すりを探している）。

## 仕組み（分かる人向け）

1. シーンを読み込んだら、`Fence_Front` を子に持つ物（＝輸送機）に `SpaceJunkGoalFence` を自動で付ける
2. 手すりに当たり判定（箱）を足す。**しまうかどうか決まるまでは切っておく**（ボットの地図に手すりが入らないように。前も手すりは地図に入っていなかった）
3. 着地の時刻を待つ。時刻は試合の進行役（`SpaceJunkRound`）の、全員で同期された時計から求める（どのPCでも同じ時刻にしまう）
   - ゴールが飛んでくる演出 … 演出の始まり＋飛ぶ秒数＋設置の秒数
   - 一緒に着地する演出 … 演出の始まり＋着地の秒数
   - 演出なし・進行役が無いシーン … すぐ
4. 着地したら、手すりごとに外側の3か所（中央と両端寄り）の真下を調べ、**2か所以上に床があれば**しまう。残す手すりだけ当たり判定を入れる
5. しまう手すりを、手すりの高さぶん下げ、下げ終えたら見えなくする
6. 手すりの材質は、本体の材質（試合中はチームの色が入った物）にそろえる

詳しくは `Documents/スクリプトの説明/Game/Match/SpaceJunkGoalFence.md`。

## できていないこと・既知の問題

- **このプロジェクトの Unity での再生と、人が遊んでの確認がまだ。** 確かめたのは、別の空の Unity プロジェクトでの、モデルの取り込みと判定・動きだけ（進行役は代役）
- **床があるかは、そのPCの当たり判定で調べる。** どのPCでも同じステージなので同じ結果になるはずだが、着地のときに動く床が通りかかっていると、PCによって結果が変わることがありうる
- しまった手すりは見えなくなるだけで、もう一度上がることは無い（同じシーンのまま次のラウンドが始まったときだけ、上げ直して着地を待つ）
- 「床」は当たり判定があれば何でもよい（ほかの輸送機・箱の上面なども、高さが近ければ床とみなす）。検証シーンを作ったとき、となりの輸送機用に置いた床が接していて、その側の手すりまで沈んだ（間を広げて直した）
