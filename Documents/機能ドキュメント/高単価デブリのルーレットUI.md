## この機能は何か

ラウンドイベント「**期間限定高価値デブリ**」（高単価デブリ。`宇宙ごみのラウンドイベント.md`）で、どの種類の物資が高くなったかを、**ルーレット**で見せる。

- イベントが始まると、画面の上の**得点バー（時間の板）の裏から、水色の半円（ルーレット）が下りてくる**
- 半円の中に物資の画像が並んでいて、**半円の上の辺の真ん中を中心に回る**。だんだん遅くなり、**ちょうど2秒で、選ばれた種類の物資が真下（真ん中の三角の中）に止まる**（止まった瞬間、その物資がぽんと大きくなる）
- イベントが続いている間は、止まったまま出ている。イベントが終わると、得点バーの裏へしまわれる

設計図：本人の参考画像（赤と青の帯の真ん中に「時間」の丸、その下に灰色の半円と、ふちに物資の丸が3つ見える）。

## 遊ぶ人から見た動き

| いつ | どうなるか |
| --- | --- |
| イベントの前 | 何も出ない |
| 高単価デブリが始まった瞬間 | 得点バーの裏から、水色の半円が 0.25 秒で下りてくる。物資の画像が左から右へ流れる |
| 始まって 2秒 | だんだん遅くなり、**ちょうど2秒**で選ばれた種類の物資が真下で止まって、ぽんと大きくなる |
| イベントが続いている間 | 止まったまま出ている（真下の物資が、高単価の種類） |
| イベントが終わった・ラウンドが終わった | 0.25 秒で得点バーの裏へしまわれる |

- **途中から見え始めた人**（始まってから2秒以上たってから画面に出た人）には、回らずに止まった状態で出る。
- ルーレットは**イベントが始まった時刻（全員で同じ時計）から数える**ので、どのPCでも同じころに止まる。流れる途中の物資は見た目だけなので、PCごとに違ってよい。止まる物資（高単価の種類）は全員同じ。

- 前の仮の画像 `Art/Sprites/HighValueRouletteFrame.png` は、もう使っていない（消すときは Unity の中で消す）

### 別の名前の画像を使うとき

プレハブ `StarSweepers/Assets/Resources/HighValueRouletteUI.prefab` を開き、一番上の `HighValueRouletteUI` の「**素材**」の欄に画像を入れる。

| 欄 | 入れる物 |
| --- | --- |
| Item Sprites | 物資の画像。上から 物資1〜物資5 |
| Frame Sprite | ルーレットのフレームの画像 |

画像は、インスペクターで **Texture Type を `Sprite (2D and UI)`** にしておく。

## 設定できる値（インスペクターの項目）

`Assets/Resources/HighValueRouletteUI.prefab` の `HighValueRouletteUI`。

| 項目名 | 意味 | 実装したときの初期値（目安。調整で変わる） |
| --- | --- | --- |
| Item Sprites / Frame Sprite | 画像（上の「画像」） | 物資は仮・フレームは本素材 |
| **Spin Seconds** | **イベントが始まってから、物資が決まる（真下で止まる）までの秒数** | 2 |
| Spin Start Speed | 回り始めの速さ（1秒に何個の物資が真下を通るか）。決まる時刻に向けて、だんだん遅くなる | 14 |
| Rail Radius | 回る中心（半円の上の辺の真ん中）から物資の中心までの距離（レールの半径）。真下の物資が三角の中に収まる長さ | 92 |
| Item Angle | レールの上の、となりの物資との角度（度）。となりの物資が、三角の左右の扇の真ん中に来る角度 | 64 |
| Slide Seconds | 出てくるとき・しまわれるときに動く秒数 | 0.25 |
| Test Mode / Test Event Seconds | ラウンドが無くてもイベントをくり返す。**本番のプレハブではオフ**（検証シーンだけオン） | オフ / 5 |

大きさ・置き場所は、プレハブの `Clip`（切り抜き）と `Wheel`（半円）と `Window`（物資を半円の中だけに見せる切り抜き）で変えられる。初期値（1920×1080 の画面での大きさ。得点バー（フレーム版）は、横長の枠が画面の上から 110〜217、時間の板が 176〜230）：

- `Clip` … 画面の上から 110（得点バーの横長の枠の上の端）より下だけを見せる。幅 800・高さ 420
- `Wheel` … フレームの画像の大きさのまま（382×169）。上の端は画面の上から 200（時間の板の裏に隠れる）。見えるのは、得点バーの下から画面の上から 369 まで
- `Window` … 半円の上の辺（画像の上から 8）より下。物資はこの上の辺の真ん中を中心に回る
- 物資の画像 … 64×64

**決まり**：

- `Item0`〜`Item6`（レールの物資の画像）は、スクリプトの Rail Items の欄に割り当ててある。**消したり減らしたりしない**（真下と左右3個ずつを回して使うため）
- 物資の画像の欄（Item Sprites）は **5つ**（物資の種類の数）

## 仕組み（分かる人向け）

> スクリプトの詳しい説明は `スクリプトの説明/Game/UI/HighValueRouletteUI.md`。

- **表示するだけ。** 高単価の種類は、ホストが決めて全員へ配っている `SpaceJunkRound` の値（`TryGetHighValueKind`）を毎フレーム読む。何も送らない
- ゲームの開始時に `Resources/HighValueRouletteUI.prefab` から1つ作り、シーンをまたいで残す（デブリセットのUIと同じやり方）
- 並び順は 9。得点バー（10）のすぐ奥なので、**半円の上の部分は得点バーと時間の板の裏に隠れる**
- 回り方は、デブリセットのスロットと同じ `1 − (1 − t)²`（`DebrisSetUI.ReelPosition` を使っている）。決まる時刻に、選ばれた物資がちょうど真下（角度 0）に来る

## できていないこと・既知の問題

- **物資の画像は仮。** 本素材が来たら `デブリセットのUI.md` の手順で差し替える
- **2026/11/26 の置き直しは、画面なしの Unity で得点バーと並べた止まった画像で確かめただけ**（回っているところ・本物の試合・人の目では見ていない）。デザイン案の写真に合わせ、時間の板の下に半円が出る位置にした。左右の物資が時間の板に隠れないよう、写真より少し（30）下げてある
- 今の仮の画面（`SpaceJunkMatchUI`）は、ラウンド数の見出しとイベントの一行（「イベント：〜　残り ○ 秒　紫（回路基板）のデブリが +2点」）を時間の丸のすぐ下の真ん中に出していて、ルーレットと重なっていた。**ルーレットが出ている間は、この2行をルーレットの下へずらす**ようにした（左のチームの行はそのまま）。また、イベントの一行の「紫（回路基板）のデブリが +2点」は、**ルーレットが止まってから（2秒後から）出す**ようにした（2026/11/26 までは始まった合図の大きな文字で行っていた。その文字はやめた）（回っている間に答えが見えないように）。仮の画面は画面なしの Unity では写らないので、**文字の位置は画面では確かめていない**（試合で、ルーレットの下の端の高さと「回っているか」の値が正しく出ることは確認）
- 得点バーが置かれていないステージでは、仮の画面が残り時間の大きな数字を画面の上の真ん中に出すので、ルーレットの上の端と重なる
- 得点バーが置かれていないステージがあれば、半円の上の端を隠す物が無いので、半円の上の辺までまるごと見える（2026/11/26 に確かめたときは、全ステージにフレーム版の得点バーが置いてあった）
- **別のPC（参加者）の画面では、まだ確かめていない。** 値は全員に配られている物を読むだけなので同じになるはず
- 出る物資が1種類しかないマップでは、同じ物資が並んで回る（流れて見えにくい）
